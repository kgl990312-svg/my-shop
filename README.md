## 3. 사용 기술

- **React, Vite**: 네비게이션 바·버튼·안내창처럼 여러 화면에 반복되는 요소를 컴포넌트로 재사용하고, 빠르게 미리보며 개발하기 위해

- **Figma**: 기획·디자인 (사이트맵, 와이어프레임)
- **Claude**: 바이브코딩 (화면 구현)
- **Antigravity**: 바이브코딩 개발 환경

## 4. 주요 기능

- **케이스 꾸미기**: 케이스 4종(원형·둥근 정사각형·하트·꽃)과 색을 고르고 스티커·큐빅·각인을 붙여 이동·크기 조절·회전, 되돌리기·다시 실행
- **로그인 없는 주문 흐름**: 꾸미기 → 확인 → 장바구니 → 주문 정보 → 주문 완료, 새로고침해도 꾸민 상태와 장바구니 유지
- **완성 이미지 저장**: 주문 완료 화면에서 꾸민 케이스 이미지를 저장
- **반응형 레이아웃**: 데스크탑 기준으로 설계하고, 휴대폰·태블릿 같은 터치 기기에 맞춘 화면 추가

## 5. 트러블슈팅

### 이슈 1: 큐빅이 케이스에 붙지 않고 떠 보임

- **문제**: 꾸미기 화면과 후기 사진에서 큐빅이 케이스 위에 둥둥 떠 있는 것처럼 보임
- **원인**: 큐빅 아래 그림자가 없고, 처음 크기가 커서 스티커와 어울리지 않고 혼자 튀어 보였음
- **해결**: 큐빅 아래에 얇은 그림자를 넣고, 기본 크기를 줄이고, 큐빅이 붙어 보이는 후기 사진으로 교체

### 이슈 2: 모바일만 고치려 했는데 데스크탑 화면도 바뀜

- **문제**: 모바일 대응 중 더 나은 구현이 떠올라 반영을 요청하면서 데스크탑은 고치지 말라고 했지만, 데스크탑의 문구와 호버 효과 일부가 바뀜
- **원인**: AI가 모바일용 수정을 따로 두지 않고 데스크탑과 같이 쓰는 코드에 바로 고쳐 넣었음
- **해결**: 바뀐 데스크탑 코드는 원래대로 되돌리고, 휴대폰·태블릿 같은 터치 기기에서만 적용되는 코드를 따로 덧붙이는 방식으로 다시 구현

## 6. AI 활용 방식

- **맡긴 일**: 기획 문서와 AI 작성 규칙을 바탕으로 화면구현하고 결과를 직접확인해 승인하거나 수정 요청함. 상품·후기 이미지 생성 프롬프트 작성
- **핵심 프롬프트**: "너무 스티커 붙여 놓은 듯 보이지 않아? 이 부분 수정 프롬프트 작성해줘", "큐빅이 너무 튀어나온 거 같아"

## 7. 회고

- **배운 점**: 원하는 내용을 문서로 정리해서 AI에게 요청하니 내가 생각했던 것과 비슷하게 만들어 줬다. 다만 "데스크탑은 고치지 마"처럼 범위를 정해 줘도 그대로 지켜지지 않을 수 있어서, 결과를 직접 확인하는 과정이 여러 번 필요하다는 걸 알게 됐다.
- **아쉬운 점**: 데스크탑 기준으로 먼저 만들고 모바일을 나중에 덧붙이다 보니 구현하면서 화면이 여러 번 바뀌었다. 기준은 데스크탑으로 정하더라도 처음부터 모바일을 함께 생각하며 만들었다면 더 효율적이었을 것 같다.
