## 3. 사용 기술

- **React, Vite**: 네비게이션 바·버튼·안내창처럼 여러 화면에 반복되는 요소를 컴포넌트로 재사용하고, 빠르게 미리보며 개발하기 위해
- **GitHub Pages**: 무료 배포
- **Figma**: 기획·디자인 (사이트맵, 와이어프레임)
- **Claude**: 바이브코딩 (화면 구현)
- **Antigravity**: 바이브코딩 개발 환경

## 4. 주요 기능

- **케이스 꾸미기**: 케이스 4종(원형·둥근 정사각형·하트·꽃)과 색을 고르고 스티커·큐빅·각인을 붙여 이동·크기 조절·회전, 되돌리기·다시 실행
- **로그인 없는 주문 흐름**: 꾸미기 → 확인 → 장바구니 → 주문 정보 → 주문 완료, 새로고침해도 꾸민 상태와 장바구니 유지
- **완성 이미지 저장**: 주문 완료 화면에서 꾸민 케이스 이미지를 저장
- **반응형 레이아웃**: 데스크탑 기준으로 설계하고, 휴대폰·태블릿 같은 터치 기기에 맞춘 화면 추가

## 5. 트러블슈팅

### 이슈 1: 큐빅이 케이스에 붙지 않고 떠 보임

- **문제**: 꾸미기 화면과 후기 사진에서 큐빅이 케이스 위에 둥둥 떠 있는 것처럼 보임
- **원인**: 큐빅 아래 그림자가 없고, 처음 크기가 스티커보다 커서 혼자 튀어 보였음
- **해결**: 큐빅 아래에 얇은 그림자를 넣고 크기를 줄이고, 큐빅이 붙어 보이는 후기 사진으로 교체

### 이슈 2: 일부 버튼 글자가 배경과 비슷해 잘 안읽힘

- **문제**: 꾸미기 화면에서 선택한 도구 이름과, 테두리 버튼에 호버상태에서 글자가 잘 안읽힘.
- **원인**: 글자색과 배경색이 너무 비슷하게 밝아서 웹 접근성 기준에 못 미쳤음. 마우스 올린 상태까지 검사하지 않아 처음에 문제를 찾지 못했음
- **해결**: 글자색을 더 진한 코랄색으로 바꾸고, 호버 상태에서 직접 확인함.

## 6. AI 활용 방식

- **맡긴 일**: 기획 문서와 AI 작성 규칙을 바탕으로 화면을 구현하고 결과를 직접확인해 승인하거나 수정 요청함. 상품·후기 이미지 생성 프롬프트 작성
- **핵심 프롬프트**: "큐빅이 너무 튀어 나와보여 프롬프트 다시 작성해줘","버튼 글자가 배경에 묻혀 잘안보여 웹접근성 기준확인해서 수정해줘"

## 7. 회고

- **배운 점**
  - 원하는 내용을 문서로 정리해서 AI에게 요청하니 내가 생각했던 것과 비슷하게 만들어 줬음. 다만 작은 디테일까진 AI가 스스로 찾지 못해 결과를 보고 무엇이 이상한지 구체적으로 말해줘야 고쳐줬음.
  - 눈으로 보기에 괜찮은 색도 웹접근성 기준에 못 미칠 수 있으므로, 호버 상태에서도 확인하는 과정이 꼭 필요하다는 걸 알게 되었음.
- **아쉬운 점**
  - 큐빅과 스티커의 크기와 그림자를 디자인 단계에서 미리 정했으면 여러번 이미지를 수정할 일이 없었을 것 같음
  - 호버상태의 글자색도 디자인 단계에서 색을 정할 때 웹접근성 기준을 먼저 확인한 후 구현했다면 나중에 다시 고칠 일이 없었을 것 같음
