> "✏️ 직접 채우기"는 문서에서 확인되지 않아 직접 채워야 하는 부분입니다.

## 01. 인트로

- **프로젝트명**: 모아(MOA). "모으다·모이다"에서 온 이름으로, 큐빅·스티커·각인을 모아 나만의 쿠션 케이스를 완성한다는 뜻이다.
- **프로젝트 성격**: 실제 브랜드가 아닌 **가상 브랜드 사이트**다. 로그인 없이 구매하는 흐름이고, 실제 결제창은 없다. 회사 정보와 후기는 가상 사이트용 예시다.
- **한 줄 설명**: 나만의 쿠션 케이스, 모아에서 완성해요. 케이스 종류와 색을 고르고, 스티커·큐빅·각인으로 직접 꾸며 확인하고 주문하는 사이트.
- **배포 링크**: https://kgl990312-svg.github.io/my-shop/
  - GitHub: https://github.com/kgl990312-svg/my-shop
  - Figma: https://www.figma.com/design/FfltZMiyfu0F665yMG5CX8/%EB%AA%A8%EC%95%84-MOA-?node-id=7-2&t=sfNIq7Kgrmv9SrLB-1
- **기간**: 2026.11.12 ~ 2026.11.17 (6일)
- **나의 역할**: 개인 프로젝트 (기여도 100%)
  - 기획: 목적, 구조, 사이트맵, 와이어프레임
  - 디자인: Figma 사이트맵·와이어프레임, 디자인 시스템, 시각 디자인 시안
  - 퍼블리싱·바이브코딩: Claude로 화면 구현, GitHub Pages 배포
- **Tech & Tools**: React 18, Vite 5, react-router-dom, 기본 CSS / GitHub Pages(GitHub Actions 자동 배포) / Figma / Claude / Antigravity
- **포커스**: 쿠션 케이스를 직접 꾸미는 인터랙션을 데스크탑과 터치 기기 각각에 맞게 설계하고 테스트로 확인한 과정.

## 02. 기획 의도

- **프로젝트 성격**: AI 바이브코딩으로 방문자가 직접 만지고 꾸며 보는 **체험형(인터랙티브) 사이트**를 만드는 프로젝트다. 소재인 "모아"는 실제 브랜드가 아닌 **가상 브랜드**이고, 실제 결제는 일어나지 않는다.
- **소재 선택**: 폰케이스나 옷은 내 취향대로 꾸밀 수 있는데, 매일 꺼내 쓰는 화장품은 왜 내 마음대로 꾸밀 수 없을까? 이 생각에서 "직접 꾸미는 체험"을 담을 소재로 쿠션 케이스를 골랐다. 스티커·큐빅·각인을 붙이고 옮기는 과정 자체가 인터랙션이 되는 소재다.
- **목표**: 방문자가 느끼길 원한 감각은 다음 세 가지다.
  - 남들과 다른 나만의 물건을 갖는 기분
  - 직접 꾸미는 재미
  - 완성한 걸 자랑하는 즐거움
- **타깃 사용자**: 직접 쓸 케이스를 꾸미려는 10대 후반~20대 초반 여성 (고등학생, 대학생, 사회초년생)
  - 다꾸·폰꾸처럼 물건 꾸미기를 좋아하고, 완성한 것을 SNS에 올리며, 회원가입이나 복잡한 결제를 귀찮아한다.
  - 이 특징은 조사 결과가 아니라 **기획 단계의 가정**이다.
- **타깃 페르소나**: 위 타깃 사용자와 기획 가정을 바탕으로 만든 가상 인물이다.
  - **기본 정보**
    - 가명: 한소윤
    - 연령대: 20대 초반 여성, 21세 대학생
    - 특징: 다꾸(다이어리 꾸미기)와 폰꾸(폰 꾸미기)를 좋아하고 스티커를 모은다. 내 취향이 담긴 물건은 SNS에 올리고 친구에게 자랑한다.
  - **상황**
    - 쿠션 팩트를 파우치에 넣고 매일 들고 다니며, 친구들 앞에서도 자주 꺼낸다.
    - 부담 없는 가격의 작은 소품을 자주 산다.
    - 폰케이스는 스티커와 큐빅으로 직접 꾸며 쓰는데, 쿠션 팩트는 매장에서 산 그대로 쓰고 있다.
  - **이 사이트를 사용하는 상황**
    - 수업이 끝나고 집에 와서, SNS에서 본 꾸민 화장품 케이스 사진을 떠올리며 노트북으로 모아에 들어온다.
    - 메인에서 케이스 종류 카드에 마우스를 올려 꾸민 예시를 보고, 가장 마음에 드는 모양을 고른다.
    - 꾸미기 화면에서 곰돌이 스티커와 핑크 하트 큐빅을 붙이고 이니셜을 각인한 뒤, 완성 이미지를 저장해 SNS에 올린다.
  - **불편함 (페인포인트)**
    - 폰케이스나 옷은 내 취향대로 꾸밀 수 있는데, 매일 꺼내 쓰는 화장품 케이스는 꾸밀 수 없다.
    - 남들과 다른 나만의 물건을 갖고 싶지만, 시판 쿠션 팩트는 디자인이 정해져 있어 다른 사람과 겹친다.
    - 회원가입이나 복잡한 결제 과정을 귀찮아해서, 가입을 요구하는 쇼핑몰에서는 구매를 미루거나 그만둔다.
    - 직접 꾸민 결과물을 친구에게 자랑하고 싶은데, 완성 모습을 깔끔한 이미지로 남길 방법이 없다.
- **배경과 목표의 연결**: 사용자 특징과 페르소나의 페인포인트가 그대로 기능으로 이어지도록 정했다.

  | 사용자 특징·페인포인트 | 사이트 기능 |
  | --- | --- |
  | 꾸미기·스티커를 좋아함, 화장품 케이스는 꾸밀 수 없음 | 스티커·큐빅·각인으로 직접 꾸미는 꾸미기 화면 |
  | 남들과 겹치는 디자인 | 케이스 종류 4가지 × 색 5가지 + 자유 배치 |
  | 회원가입·복잡한 결제가 귀찮음 | 로그인 없이 구매, 장바구니 |
  | 완성한 걸 자랑하고 싶음 | 완성 이미지 저장하기 |
  | 감성적인 취향 | 감성적이고 아기자기한 분위기 |

## 03. 핵심 가설

- **가설 설정 배경**: 폰케이스는 직접 꾸미면서 쿠션 팩트는 그대로 쓰는 한소윤에게, 붙이고 바로 고칠 수 있는 꾸미기 화면이 있으면 꾸미기를 끝까지 이어 갈 것이라는 기획 가정에서 세웠다.
- **IF**: 상품 상세에서 "꾸미기 시작"을 누르면 빈 케이스 위에 스티커·큐빅·각인을 붙이고, 끌어서 옮기고, 크기를 조절하고, 회전할 수 있는 꾸미기 화면(P03)을 제공하면
- **THEN**: 한소윤 같은 타깃 사용자는 꾸미기를 중간에 멈추지 않고 "완료"를 눌러 **확인 화면(P04)까지 이동할 것이다.**
- **검증 방향**: 07의 TC-11(완료 → 확인 화면)과 사용 흐름 TC-26·TC-27로 기능이 막힘 없이 이어지는지 확인한다. 실제 사용자가 P04까지 가는지는 동료 1명이 안내 없이 실제 기기로 해 보는 모습을 보고 확인한다.
  - 관찰 기준: 안내 없이 "완료"를 눌러 확인 화면(P04)까지 가는지

## 04. 레퍼런스 & 비주얼 디렉션

- **디자인 시스템**: 이 프로젝트는 **자체 디자인 시스템 "모아(MOA)"를 만들어 사용**했다. 컬러·글꼴·간격·모서리·컴포넌트를 정했고, 정리 문서는 `docs/06-site-design.md`에 있다. 무드 시안과 스타일 보드는 따로 만들지 않고 시각 디자인 시안과 디자인 시스템으로 대신했다.
- **레퍼런스**
  - 베이직 톤 쿠션 케이스 사이트 이미지 → 영문 필기체 포인트를 가져와 P01 소개 배너의 "Make it yours" 한 줄에 적용했다.
    - ✏️ 직접 채우기: 레퍼런스 사이트 이름 또는 이미지
- **비주얼 디렉션 한 줄**: 화면은 깔끔하게 비우고, 아기자기함은 스티커·일러스트·작은 반짝이에만 담는 "차분한 바탕 위의 귀여운 포인트".
  - 꾸밈 이미지는 "미니멀 엘레건스". 한 케이스에 요소 2~3개만, 넉넉한 여백. 원색과 많은 요소는 피한다.
- **컬러**: 베이지를 섞은 소프트 핑크·코랄 톤, 밝은 테마 하나

  | 쓰는 곳 | 색 |
  | --- | --- |
  | 페이지 배경 | #FBF6F0 |
  | 면 (배너, 선택한 항목) | #F7E6DF |
  | 포인트 (핵심 버튼, 가격, 로고) | #C4513F |
  | 본문 글자 | #3D2E28 |
  | 장식 (별점, 반짝이) | #E8786E, #F6B4AC |

  - 포인트 코랄은 아껴 쓴다. 한 화면에 핵심 버튼 하나, 가격, 로고, 필수 표시(*)에만 쓴다.
  - **컬러 선택 이유**: 소프트 핑크·코랄은 쿠션 팩트 같은 화장품 패키지에서 익숙한 색이라 "화장품 케이스를 꾸민다"는 주제가 바로 느껴지게 했다. 베이지를 섞은 바탕은 화면을 차분하게 눌러 줘서, 사용자가 붙이는 스티커·큐빅이 주인공이 되게 한다. 포인트 코랄을 아껴 쓰는 것도 같은 이유다.
- **타이포그래피 방향**
  - 제목·본문: Pretendard (굵기 400·600·700·800). 한글이 작은 크기에서도 또렷하고 굵기 종류가 많아, 글꼴 하나로 제목부터 본문·가격까지 위계를 나눌 수 있어서 골랐다. 장식이 없는 글꼴이라 아기자기한 이미지와 부딪히지 않는다.
  - 포인트: Great Vibes(영문 필기체). P01 소개 배너의 "Make it yours" 한 줄에만 써서 감성을 한 번만 강하게 준다. 레퍼런스에서 가져온 부분이다.
  - 글자 크기는 14px 이상, 짝수 크기만 쓴다.
- **인터랙션 무드**: 느리고 부드럽게 — 0.3초 ease로, 사용자가 건드린 것 하나만 움직이고 화면 전체는 가만히 있다.

## 05. 인터랙션 설계

### 사이트 구성 한눈에 보기

```
P01 메인 ──(케이스 종류 카드)──▶ P02 상품 상세 ──(꾸미기 시작)──▶ P03 꾸미기 ★
                                                                     │ 완료
                                                                     ▼
P06 주문 완료 ★ ◀──(결제하기)── P05 주문 정보 ◀──(바로 구매하기)── P04 확인
                                     ▲                               │ 장바구니 담기
                                     └──────(주문하기)── P07 장바구니 ◀┘
```

- 핵심 흐름: 꾸미기 → 확인 → 주문하기 / 보조 흐름: 케이스 종류 둘러보기
- ★ 핵심 인터랙션 위치: P01 케이스 종류 카드, P03 꾸미기 편집 영역, P06 완성 이미지
- 사이트맵: https://www.figma.com/design/FfltZMiyfu0F665yMG5CX8/%EB%AA%A8%EC%95%84-MOA-?node-id=1-6

### 인터랙션 1. 꾸미기 편집 (P03) — 가설의 IF

- **무엇을**
  - 큐빅(8개)·스티커(8개) 목록에서 누르면 케이스 가운데에 붙고 선택 상태가 된다.
  - 선택 상자로 이동, 모서리로 크기 조절, 회전, X로 하나만 삭제할 수 있다. 안쪽 점선(꾸밀 수 있는 범위) 밖으로는 나가지 않는다.
  - 각인은 6가지 스타일(글꼴 2 × 색 3) 중 하나를 고르고 10자까지 입력하면 케이스에 바로 반영된다.
  - 도구 패널은 아래에서 12px 올라오며 열린다(0.25초).
  - 스티커·큐빅·각인이 없으면 "완료"가 비활성화된다.
- **왜**: 사용자 특징 "꾸미기·스티커를 좋아함"에 맞춰, 직접 꾸미는 재미를 사이트의 중심 경험으로 두었다. 페르소나의 페인포인트 "화장품 케이스는 꾸밀 수 없다"를 직접 해결하는 화면이다. 붙이고 바로 고칠 수 있어야 꾸미기를 끝까지 이어 가 확인 화면으로 간다고 보았다.
- **어떻게**
  - 데스크탑: 목록에서 캔버스로 끌어다 놓기도 가능하다.
  - 터치 기기(1024px 이하): 탭하면 가운데에 붙고, 붙은 스티커를 끌어 옮긴다. 스티커 위에서 두 손가락으로 벌리면 크기, 돌리면 회전한다. 입력 종류(`pointerType`)로 마우스와 손가락을 나눠 처리했다.
  - 되돌리기·다시 실행, 새로고침해도 꾸민 상태 유지.

### 인터랙션 2. 케이스 종류 카드 꾸민 예시 미리보기 (P01)

- **무엇을**: 카드에 마우스를 올리면 꾸미지 않은 케이스가 꾸민 예시 이미지로 0.3초 동안 부드럽게 바뀌고, "꾸민 예시" 표시가 붙는다. 마우스를 떼면 원래대로 돌아온다.
- **왜**: 꾸미기 전에 완성된 모습을 먼저 보여 줘서 상세와 꾸미기로 들어가게 하려고 했다. 페르소나 한소윤도 꾸민 예시를 보고 마음에 드는 모양을 고른다.
- **어떻게**: 꾸미지 않은 이미지 위에 꾸민 이미지를 겹치고 투명도를 바꾼다. 터치 기기에서는 처음부터 꾸민 예시를 보여 주는 방식을 시도했지만, 후기와 헷갈려서 기본 사진만 보여 주기로 정했다.

### 인터랙션 3. 완성 이미지 반짝임과 이미지 저장 (P06)

- **무엇을**: 주문 완료 화면에 들어오면 완성 이미지가 커지며 나타나고, 체크 배지가 도장처럼 찍힌 뒤 하얀 빛줄기가 대각선으로 한 번 지나간다(0.8초). 이어서 주변 반짝이 별 3개가 차례로 나타나 살짝 커졌다 작아지기를 반복한다(3.6초마다). 아래 문구와 주문 정보도 차례로 올라온다(전체 약 1.3초). 데스크탑에서는 이미지에 마우스를 올리면 빛줄기가 한 번 더 지나간다. "이미지 저장하기"로 완성 이미지를 저장한다.
- **왜**: 사용자 특징 "완성한 걸 자랑하고 싶음"에 맞춰 완성 이미지 저장 기능을 넣었다. 페르소나의 페인포인트 "완성 모습을 깔끔한 이미지로 남길 방법이 없다"를 해결한다. 반짝임은 완성한 순간을 기분 좋게 마무리하려는 장치다.
- **어떻게**
  - 저장 이미지는 화면과 같은 값으로 그려 PNG로 만든다(`exportImage.js`).
  - 안드로이드는 다운로드하면 갤러리 Download 앨범에 저장된다. 아이폰은 웹사이트가 사진 앱에 바로 저장할 수 없어서, 이미지를 크게 띄우고 길게 눌러 저장하게 했다.
  - 움직임 줄이기 설정에서는 반짝임 없이 바로 보여 준다.

## 08. 바이브코딩 구현

- **협업 방식**: AI가 가장 먼저 읽는 프로젝트 설명서(`PROJECT_CONTEXT.md`)를 만들고, AI가 한 단계씩만 진행한 뒤 결과를 보여 주면 내가 "승인 / 수정 요청 / 다시 하기"로 검토했다. 코드 리뷰처럼 매 단계 결과를 확인하고 다음으로 넘어가는 방식이었다.
- **구현 환경**: React 18 + Vite 5 + JavaScript + 기본 CSS, react-router-dom / GitHub Pages(main에 push하면 GitHub Actions가 빌드·배포) / Claude(구현), Antigravity(개발 환경)
- **내가 설계한 것**
  - 기획 문서: 목적, 구조, 사이트맵, 와이어프레임, 인터랙션 목록
  - AI 작성 규칙: 문서에 있는 내용만 쓰기, 비어 있는 항목은 질문하기, 출처 표시
  - 진행 순서 7단계: 목적·범위 확인 → 페이지 설계 → 디자인 쌓기 → 에셋 삽입 → 인터랙션 → 반응형 → 배포
  - 모바일 "절대 규칙": 데스크탑(1025px 이상) 화면과 동작은 바꾸지 않는다. 모든 변경은 모바일 전용 코드를 덧붙이는 방식으로 한다
  - 처음 분석한 인터랙션 65개를 모바일에서 유지 47 / 축소 12 / 제거 6으로 나눈 기준 (이후 8개를 추가해 지금은 73개, 그중 공유하기 1개는 뺌)
- **AI에게 맡긴 것**
  - 기획 문서를 바탕으로 한 화면 구현 (페이지·컴포넌트·CSS·인터랙션 코드)
  - 상품·후기 이미지 생성 프롬프트 작성
  - 모바일 대응 분석: 인터랙션을 하나씩 살펴 유지·축소·제거로 나누는 초안과, 터치 기기 전용 코드 작성
  - 테스트 케이스(35개) 작성과 결과 정리, 문서(인터랙션 목록·수정 내역) 갱신
  - 비어 있던 품질 기준(지원 브라우저, 태블릿 가로, 접근성, 로딩 시간)의 추천안과, 실패한 접근성·로딩 시간 문제의 원인 분석·수정
- **내가 직접 판단하고 수정한 것**
  - 이미지: 생성 이미지를 보고 "너무 스티커 붙여 놓은 듯 보이지 않아?", "큐빅이 너무 튀어나온 거 같아"라고 판단해 수정 프롬프트를 요청했다.
  - 데스크탑 침범: 모바일 수정이 데스크탑까지 바꾼 것을 발견하고, 절대 규칙을 세워 다시 구현하게 했다. (07의 수정 2번)
  - 꾸민 예시: 터치 기기에서 처음부터 보여 주는 방식을 써 봤지만 후기와 헷갈려서 되돌렸다.
  - 공유 버튼: 넣었다가 뺐다. 이미지 저장하기와 하는 일이 겹쳐서, 공유는 저장한 이미지를 갤러리·사진첩에서 보내도록 했다. 아이폰은 저장 화면의 길게 누르기 메뉴에도 공유가 있다.
  - 장바구니: 디자인을 복사하는 "다시 꾸미기"를 넣었다가, 원래 카드를 고치는 "수정하기"만 남겼다.
  - 품질 기준: AI가 추천한 기준(WCAG 2.1 AA 명도 대비, 모바일 LCP 2.5초 이하 등)을 검토해 정하고, 실패한 2건을 그 기준에 맞춰 고치게 했다.

## 09. 회고

- **배운 점**: 원하는 내용을 문서로 정리해서 AI에게 요청하니 내가 생각했던 것과 비슷하게 만들어 줬다. 다만 "데스크탑은 고치지 마"처럼 범위를 정해 줘도 그대로 지켜지지 않을 수 있어서, 결과를 직접 확인하는 과정이 여러 번 필요하다는 걸 알게 됐다.
- **잘된 것**
  - 꾸미고, 확인하고, 주문하는 과정이 컴퓨터와 휴대폰 모두에서 막힘 없이 끝까지 이어졌다.
  - 휴대폰에서도 손가락으로 톡 눌러 스티커를 붙이고, 두 손가락으로 크기를 바꾸고 돌릴 수 있게 만들었다.
  - 꾸민 케이스를 화면에 보이는 그대로 사진으로 저장해서, 휴대폰 사진첩에 남길 수 있게 했다.
- **잘못된 것 (아쉬운 점)**: 데스크탑 기준으로 먼저 만들고 모바일을 나중에 덧붙이다 보니 구현하면서 화면이 여러 번 바뀌었다. 기준은 데스크탑으로 정하더라도 처음부터 모바일을 함께 생각하며 만들었다면 더 효율적이었을 것 같다.
- **도전한 것**: 기획 문서와 규칙을 정리해서, AI에게 한 단계씩 시키고 결과를 직접 확인하며 사이트 만들기
- **다음에 개선할 것**
  - 컴퓨터 화면을 먼저 만들더라도, 처음부터 휴대폰 화면도 같이 생각하며 만들기
  - 내가 상상한 사용자 모습이 맞는지, 실제 10대 후반~20대 초반 사람들에게 직접 물어보기
  - 눈이 잘 안 보이는 사람도 쓰기 편하게, 글자와 배경 색이 잘 구분되는지 기준 정하기 → 2026-11-23에 기준(WCAG 2.1 AA)을 정하고 고침 (07 참고)
  - 아이패드를 가로로 돌리면 컴퓨터처럼 바뀌어 손가락으로 크기·회전을 바꿀 수 없다. 이 부분 고치기
  - 예상 배송일을 계산할 때 공휴일도 빼고 계산하기

## 10. 가설 검증

- **처음과 끝을 연결하는 서사**: "화장품은 왜 내 마음대로 꾸밀 수 없을까"에서 시작해, 한소윤처럼 폰케이스는 꾸미면서 쿠션 팩트는 그대로 쓰던 사용자가 직접 꾸미고 완성 이미지까지 저장하는 흐름을 만들었다.
- **검증 근거**: 동료 1명이 안내 없이 실제 기기로 꾸미기를 끝내고 "완료"를 눌러 확인 화면(P04)까지 이동했고, 같은 흐름은 TC-11·TC-26·TC-27로 데스크탑과 휴대폰 모두 통과했다. 다만 1명의 결과라 타깃 사용자 전체로 일반화하기는 어렵다.
